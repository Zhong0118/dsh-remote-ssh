# DSH 0.1.7 Remote SSH Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adapt the Web Remote SSH bundle to DSH `0.1.7-rc.2`, reinstall from GitHub, and push the verified branch.

**Architecture:** Keep the existing SSH transport/routers and global dual-shell + agent-scoped policy, whose interaction with the new preset registry must be tested against real 0.1.7 packages. Replace the stale search hook barrier with an inject on the real preset registry; migrate the Plugins tab slot and rebuild against matching DSH packages. Validate the actual profile and browser rather than relying only on mocked tests.

**Tech Stack:** TypeScript, Cordis, DSH packages `0.1.7-rc.2`, pnpm, Vitest, React, YAML.

**Spec:** `docs/superpowers/specs/2026-09-28-dsh-017-compat-design.md`

## Global Constraints

- Preserve SSH config/keys, remote files, workspace and Session history, existing profile dependencies/patches, and `.dsh-meow/`.
- Keep fail-closed routing, Web-only client, unchanged native tool names, POSIX/Linux remote and Windows host support.
- No SSH host supplied: real remote execution remains untested.
- Do not modify DSH checkout or start a replacement Web server.
- Existing Web profile does not currently install the plugin; install from `github:Zhong0118/dsh-remote-ssh#web-dsh-rc8` after pushing.
