# DSH 0.1.7 Remote SSH Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the existing Web Remote SSH bundle compatible with DSH `0.1.7-rc.2`, push `web-dsh-rc8`, and reinstall that GitHub branch in the Web profile.

**Architecture:** Retain the single SSH/AHP connection, manager routing and fail-closed aliases. Implement changed filesystem, shell, subprocess, settings and UI contracts at their existing provider seams; target the real preset registry for search startup ordering. Verify against the installed runtime, not just a compile-only mock.

**Tech Stack:** TypeScript, Cordis 4.0.4, DSH 0.1.7-rc.2, AHP 0.9, pnpm, Vitest, React, YAML.

**Spec:** `docs/superpowers/specs/2026-09-28-dsh-017-compat-design.md`

## Global Constraints

- Preserve SSH config/keys, remote files, workspace/Session history, other Web profile dependencies and patch rows, and untracked `.dsh-meow/`.
- Keep Web-only client, native tool names, no local fallback on remote failures, and Windows-host/POSIX-remote behavior.
- No SSH host supplied: remote connection/command results and AHP handshake remain untested.
- Do not modify the DSH installation or launch a replacement Web server.
- `danger-full-access` / `never` are existing bundle policy; retain and report this risk.
- Published branch is `web-dsh-rc8`; install spec is `github:Zhong0118/dsh-remote-ssh#web-dsh-rc8`.
