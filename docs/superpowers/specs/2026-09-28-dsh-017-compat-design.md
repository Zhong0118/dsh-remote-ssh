# DSH 0.1.7-rc.2 Remote SSH Compatibility Design

## Goal and boundary

Update the existing Web-only `dsh-remote-ssh` bundle from the DSH `0.1.2-rc.1` package surface to the locally installed, registry-current `0.1.7-rc.2`. Preserve transparent LOCAL/SSH execution, fail-closed removed remote workspaces, persistent server/workspace/session records, and Windows-host/POSIX-remote support. Do not modify SSH keys, SSH host configuration, unrelated profile plugins, the DSH checkout, or the pre-existing untracked `.dsh-meow/` directory. No remote host was nominated: live SSH execution will be explicitly reported unverified.

## Evidence and compatibility changes

The installed Web composition no longer contains `agent-presets`; it has `agent-preset-registry` and `preset-standard` with agent-scoped shell and search tools. Host shell and search rows are disabled. The old bundle's patch for `agent-presets` is skipped; however, the plugin itself supplies both shell tools at host level, so the global readiness precondition can succeed once those providers mount. The current tools API restricts known inherited tools, including preset ancestor layers, but cannot restrict unknown names; the old global-tool readiness assumption must be tested against actual profile composition. On Windows, stock preset defaults to pwsh only, but a POSIX remote requires bash. The Plugins settings shell now declares `settings.plugins.tab` rather than `settings.plugin.item`. The existing Web profile does not currently contain an active remote-ssh installation.

## Composition and agent lifecycle

Retain the current SSH/AHP transport, manager, filesystem/subprocess/spill routers, local provider isolation, and `danger-full-access`/`never` security boundary. Make the bundle's preset integration target rows and APIs present in the new composition. Keep the existing host-level dual shell providers and bind each agent after both are registered; preset tools are inherited into the agent scope, so the existing scoped restriction hides the opposite dialect and a remote-scoped shell presentation may shadow the selected inherited provider. Verify this against the real DSH 0.1.7 scoped registry and on Windows-local/POSIX-remote cases before changing working code. Keep the local host's native dialect (bash on POSIX, pwsh on Windows) and ensure the opposite dialect does not become model-visible. Reconcile agent creation, disposal, and preset changes using the plugin's existing global pair of shell tools, rather than assuming the upstream Web host still supplies them. The shared routing boundary rejects stale/removed remote mappings rather than falling back to the host. Preserve native tool names and contracts: do not add `remote_*` tools.

The search path normalization mechanism must be active before each relevant preset-scoped search tool loads; patch the real `agent-preset-registry` row with its existing `loader` and `sessionProjections` injects plus `remoteSshSearchHook`, so preset mounting waits for the hook. Publish `remoteSshSearchHook` only after `registerHooks` and load-cache eviction have completed; dependency resolution can wake immediately. Do not depend on YAML row order. If the stock parser signature changes, fail explicitly rather than silently returning host paths. Do not introduce speculative abstraction layers or change unrelated preset features.

## DSH core seam migration

DSH `0.1.7-rc.2` also changes four provider contracts, not merely preset composition. Migrate both local router and AHP filesystem implementations to `readByteRange(target,{offset,length},signal)` with bounded transfer: no whole-file read or truncation masquerading as a range; route targets by their durable workspace envelope, including tombstones. AHP `resourceRead` has no range parameters, so remote range reads use the existing SSH/AHP terminal channel to run a POSIX `dd` + base64 window command with validated non-negative offset/length, bounded output, cancellation, and a clear failure if `dd` is unavailable. No remote package is installed. Migrate both shell executors from `run/start` to `execute(spec): Promise<ShellExecution>`, where an execution is published after preparation, `done` never rejects, `result()` lazily projects split output and rejects only on infrastructure failure, `observed` gives independent byte-offset readers, `readOutput` remains incremental, and `onExpiry: none` never arms a deadline. Expiry during preparation yields a settled timed-out handle; pre-publication cancellation rejects. Convert subprocess and spill callers to `execute(...).result()` without bypassing timeout or error semantics.

Migrate the routed subprocess service to current `terminalEnvironment`, `SubprocessHandle.control`, and terminal `terminalType`, `resize`, `inspectActivity` APIs. Delegate environment without cwd to local provider (remote execution is still selected by spawn cwd). Declare unsupported AHP capabilities honestly (`control` absent and explicitly reject requested control pipe; activity unknown with monotonic revision; no fabricated process group). Forward terminal resize via AHP `TerminalResized`; propagate `terminalType` to remote `TERM` and use a fixed type for the internal FIFO writer. Keep all ordinary process/PTY operations on the existing AHP host connection and preserve local provider delegation.

The old `ctx.settings.register` namespace service is gone. Use DSH's profile-backed SettingsForms / Loader config editor path for durable catalog updates: profile entry `remote-ssh-manager` is the sole persistent authority, and current config is observed on live updates. Mark manager-mutated schema fields (`servers`, `workspaces`, `sshConfigFile`, `openFileMode`, `openFileEditorPath`) volatile; keep aliasRoot/timeouts and safety policy ordinary. Consume Cordis volatile references and the owner-scoped `loader/volatile-update` notification to queue a catalog refresh, rather than holding the initial constructor values or remounting a live Agent. Disable only the auto-generated settings page for this manager, not its custom Web UI. Call `settings.replace('remote-ssh-manager', ...)` with an expected revision when available and preserve ordinary profile fields, explicit errors and atomicity. Preserve existing server/workspace values and unrelated profile patch rows; reject writes atomically when settings are read-only or validation fails. Make tests check persistence across manager reload and fail-closed tombstone behavior, not just an in-memory snapshot. Align Cordis/plugin-loader/schemastery versions with the tested DSH runtime.

## Validation and limits

Regression checks must catch absent preset rows, missing agent session binding, wrong tool visibility on POSIX and Windows, incorrect remote search path rewriting, and missing Plugins tab registration. Run the full test/build suite against updated dependencies and inspect composition on the actual installed DSH. Browser-check the existing Web GUI when practical. No remote SSH host is authorized for this run; report connection, remote file/shell/search execution, and VS Code Agent Host handshake as **not tested**, not passed. Stop on packaging, composition, install, or push failure and report the exact blocker; do not weaken SSH security or silently edit unrelated profile state.
